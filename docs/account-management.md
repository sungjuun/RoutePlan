# V20 계정 관리

V20은 마이페이지에서 계정 식별 정보를 직접 관리하고, 탈퇴 시 개인 데이터를 서버에서 함께 정리합니다.

## 사용자 흐름

| 기능 | 동작 |
| --- | --- |
| 닉네임 변경 | 2–50자로 변경하며, 이미 사용 중인 닉네임은 거부합니다. 현재 세션은 유지되고 다른 열린 세션에서도 다음 조회부터 새 닉네임이 표시됩니다. |
| 이메일 변경 | 현재 비밀번호를 다시 확인하고 새 이메일로 변경합니다. 이메일 인증 상태를 초기화하고 모든 기기에서 로그아웃한 뒤 새 주소로 인증 메일을 보냅니다. |
| 회원 탈퇴 | 현재 비밀번호와 확인 문구 `회원 탈퇴`가 모두 맞아야 처리합니다. 성공 즉시 모든 세션을 종료하고 계정과 소유 데이터를 삭제합니다. |

이메일 변경은 인증 메일을 받을 수 있어야 하므로 메일 모드가 `LOCAL` 또는 `SMTP`일 때만 허용합니다. 로컬 Compose에서는 [개발 메일함](http://localhost:8026)에서 새 주소의 인증 메일을 확인합니다.

## API

모든 경로는 `/api/v1` 기준이며 로그인과 CSRF 토큰이 필요합니다.

| 메서드·경로 | 요청 | 결과 |
| --- | --- | --- |
| `PATCH /auth/profile` | `{ "nickname": "새 닉네임" }` | 갱신된 사용자 정보, 200 |
| `POST /auth/email/change` | `{ "currentPassword": "…", "newEmail": "…" }` | 모든 세션 종료·재인증 메일 예약, 204 |
| `DELETE /auth/account` | `{ "currentPassword": "…", "confirmation": "회원 탈퇴" }` | 계정 및 개인 데이터 삭제, 204 |

요청 제한은 닉네임 변경 시간당 10회, 이메일 변경 하루 5회, 탈퇴 시도 하루 3회입니다. 비밀번호 오류는 일반 로그인 실패와 같은 응답으로 처리합니다.

## 삭제 범위와 보존 기준

Flyway **V16**은 사용자 외래 키의 삭제 정책을 명시합니다. 기능 버전 V20과 DB 마이그레이션 번호는 다릅니다.

삭제 대상:

- 사용자, 프로필 사진, 취향, 인증 토큰·메일 작업, 모든 로그인 세션
- 만든·가져온 여행과 그 장소 설정, 일정, 날씨, 예산·지출
- 공개한 루트와 그 하위 댓글·후기·좋아요·신고
- 다른 루트에 작성한 댓글·후기·좋아요·신고

다른 사용자가 작성한 신고 자체는 유지하되, 탈퇴 사용자가 처리자였던 경우 `resolved_by`만 `NULL`로 바꿔 처리자를 익명화합니다. 외부 API 집계나 원문을 저장하지 않는 해시 기반 요청 제한 기록처럼 계정 외부의 운영·보안 집계는 각 보존 기간까지 남을 수 있습니다.

삭제는 복구 기능을 제공하지 않습니다. 운영에서는 법적 보존 의무, 백업 만료, 개인정보 처리방침을 별도로 정하고 실제 배포 정책과 이 문서를 일치시켜야 합니다.
